## 2. Current assist algorithm (what it ACTUALLY is)
`ml.propose()` CPU path = **OpenCV `cv2.floodFill`, floating-range, 4-connectivity**, loDiff=upDiff=`tolerance`
(default **22**) per RGB channel, then a 5×5 morphological close, then contour extraction dropping any
contour with area < 50 px. It is **low-level colour region-growing** — no notion of objects, roofs, or planes.
- Preprocessing: none (raw RGB).
- Similarity: floating range — each candidate pixel compared to its already-filled neighbours (walks gradients).
- Connectivity: 4-connected.
- Failure modes: (a) sharp local texture edges (grout lines, tile shadows) halt growth → tiny/empty region;
  (b) smooth gradients let it leak across unrelated regions.
- **This is NOT SAM2** and is labeled `cpu_assist_fallback` everywhere (backend field, toast, badge).

## 3. Coordinate pipeline — audited, VERIFIED CORRECT
- Canvas backing store = wrapper CSS size (`c.width = w.clientWidth`); `getBoundingClientRect()` is also CSS px
  → screen↔canvas mapping is 1:1 in CSS px. `scale`/`offset` (viewRef) are computed in the same CSS-px space.
- Draw uses `translate(offset); scale(scale); drawImage(img,0,0)` in image pixels; `toImg` is the exact inverse.
- Image is EXIF-applied on BOTH sides: browser `<img>` auto-orients (naturalWidth = display dims) and backend
  `ImageOps.exif_transpose` produces the same display dims → **click on roof maps to roof pixels**.
- Device Pixel Ratio: canvas is NOT multiplied by DPR → rendering is non-retina (cosmetic softness) but
  coordinates stay consistent → **not a correctness bug**.
- **Proof it is not a coordinate bug:** the diagnostic ran the flood-fill on exact server-side image
  coordinates of a known red-tile-roof pixel and it still failed — so the failure is algorithmic, not mapping.

## 5. Root cause(s)
1. **Algorithmic (primary):** flood-fill measures colour similarity, not roof structure. Textured tile roofs
   have high local variance (grout/shadow/highlight) so growth halts (empty); smooth areas over-grow. It
   fundamentally cannot represent "one continuous roof plane bounded by the eave."
2. **Contour area filter (50 px)** turns small fragmented tile regions into "No region found".
3. Not a coordinate/EXIF/DPR bug (verified in §3).
